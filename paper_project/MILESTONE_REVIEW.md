# 关键节点反向审查制度

## 1. 目的

每个关键节点完成后，不立即把“有产物”视为“结论可信”。负责角色必须先主动寻找自身工作的失败原因、错误证据、时间风险和成本风险；P0 验收后，关键跨角色节点再交 P4 独立审查。

## 2. 强制触发节点

1. 文献与 Research Gap 冻结；
2. 研究问题或主张变更；
3. 实验协议冻结；
4. 本地实验工具实施完成；
5. 每次付费 smoke、pilot、formal 完成；
6. 人工问卷设计完成及回收完成；
7. 完整论文初稿完成；
8. 每轮导师意见修订完成；
9. 长文/短文决策门；
10. 投稿前最终版本。

## 3. 每个角色必须回答的问题

### 证据准确性

- 哪个结论最可能是错的？
- 是否存在字段错配、循环评价、引用误读、统计误用或数据泄漏？
- 哪些结论只得到间接证据，不能写成事实？
- 第三方能否从保存产物复核？

### 反例与替代解释

- 有什么反例会推翻当前判断？
- 是否存在更简单的替代解释？
- 结果可能来自模型、Prompt、token、样本选择或评审者，而不是目标组件吗？

### 截稿可行性

- 按当前进度能否在内部截止日前完成？
- 关键路径和最晚完成日期是什么？
- 哪个任务应立即删除、降级或移入附录？

### 成本可行性

- 本节点已花费、已承诺和最坏情况成本是多少？
- 是否仍处于 500 CNY 总上限、350 CNY 缩减线和阶段预算内？
- 有没有零成本替代方案？

### 决策

- `PASS`：可以进入下一阶段；
- `PASS_WITH_CONDITIONS`：列出进入下一阶段前必须完成的条件；
- `FAIL_REVISE`：必须返工；
- `STOP_OR_DOWNGRADE`：停止该方向或降为短文/附录/Limitations。

## 4. 角色分工

- P1：反审检索覆盖、引用真实性、Gap 夸大和文献时效；
- P2：反审实验公平性、数据/字段、统计、复现、时间和 API 成本；
- P3：反审论证越界、引用—论断映射、数字一致性、篇幅和截稿进度；
- P4：独立挑战 P1–P3，不接受角色自己的 PASS 作为最终依据；
- P0：整合冲突并决定继续、返工、降级或停止；
- Human PI：批准预算突破、伦理、人评和最终投稿。

## 5. 输出格式

每次反向审查保存到：

`paper_project/reviews/milestones/<date>-<agent>-<task>-reverse-review.md`

至少包含：审查对象、最强反对意见、发现、证据位置、时间影响、成本影响、剩余 Blocker、裁决和下一门准入条件。

## 6. 独立性规则

- 负责角色必须先做反向自审，但不得独自批准自己的关键结论；
- P4 在实验协议、pilot、完整初稿、长短文门和投稿前必须独立复审；
- P3 不得审定实验有效性；P2 不得审定论文新颖性；P1 不得审定统计结论；
- 若 P4 与负责角色冲突，由 P0 提交 Human PI 裁决。
