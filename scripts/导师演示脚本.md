## 3. Demo #1：筷子文化 · 英语 HSK3（最核心 · 2 分钟）

**（动作：回到首页「导师演示入口」→ 点 🥢 「筷子文化 · 英语 HSK3」卡片）**

> 我第一个展示的是英语母语、HSK3 学生、**筷子和合餐**这个点——这是一个非常经典的"跨文化差异强烈、学生容易踩雷"的场景。
>
> **（学习页加载完成，停在顶部"文化背景 / 语言点介绍 / 文化对比"三个 Tab）**
>
> **① 母语阐释打底（Tab：文化背景）**——先看这一段用英文写的文化背景，**（指 precise_definition 那行英文）** 英语母语学习者第一眼不会因为陌生文化而焦虑。
>
> **② 语言点（Tab：语言点介绍）**——**（切 Tab）** 现在切到语言点介绍：「**我吃饱了，谢谢！**」这一句是本课核心句型，**（手指把整句圈出来）** 正好对应上次系统被 LLM 写成重复字母那道题，我已修好三层清洗，不会再出现「A. A. 我吃饱了，谢谢！」。
>
> **③ 跨文化对比（Tab：文化对比）——这是系统灵魂！** **（切到文化对比 Tab，逐行念 similarities/differences）** 对比要点通常是：
> - 餐具对比：刀叉（个人工具） vs 筷子（共同夹菜 → 合餐文化）
> - **禁忌语义**：把筷子竖插到米饭里 = 给去世的人上香（这是英语文化里完全没有的禁忌）
> - 差异带来的语用："**我吃饱了，谢谢！**"≠ 真的饱了，而是礼貌拒食；英语的 I'm full 是真的饱 → 这就是我们必须做跨文化对比的原因
>
> **④ 做两道题（体现判分闭环）**
> - 第一题故意选一个"明显错"的选项（比如"你做的菜不好吃"）→ 页面会红框 + 显示**正确答案单层前缀**（之前的 A. A. 修复点）
> - 第二题选正确的那个 → 绿框 + 判 ✓
> - 所有题做完点"保存结果" → 跳回首页，**（如果是登录态，指一下画像卡右上角的锁 🔓 已登录 · 进度已绑定账号）** 成绩会 POST 到 `/api/learning/results`。
>
> **⑤ 偏见检测（口头补一句）**：A3 输出经过关键词+句式两级偏见检测，如果 LLM 写出"中国人都…"这种刻板句式，会被 A5 打回 confidence<0.6 → 不进入缓存。

## 4. Demo #2：饮食文化 · 日语 HSK3（差异化 + 迁移点 · 1 分钟）

**（动作：回到首页 → 点 🍱「饮食文化 · 日语 HSK3」）**

> 第二个演示日语母语。**为什么选日语？** 因为日语母语学习者是"汉字文化圈但文化规则完全不同"的典型，最能体现我们**「不是翻词典翻译，而是真做迁移」**的价值。
>
> 这个知识点的对比核心通常是：
> - **买单语用**：日本店里说「すみません」（抱歉/不好意思）举手，跟中文大声叫"服务员！买单！"在语气权力距离上完全相反；日语母语者直接叫服务员会被认为非常不礼貌。
> - **合餐 vs お皿分け**：日本默认分盘（お通し也是个人份）→ 对比中国合餐夹菜给客人的"热情编码"。
> - A2 的母语阐释会**用日文讲中文饮食文化**，而不是用英文（我们做了语言代码幂等处理，不会退回英语——这是之前修过的一个大 bug）。
>
> **（切到"文化对比 Tab" → 指一两个差异的 bullet 就停，不要整段念）**
>
> 好，对比就看到这儿。整个日语场景和英语场景的**架构、调用链完全一样**，只是 A2/A3 的输出由 target_culture 驱动分开缓存——这就是我系统支持 8 大母语圈的方式。

## 6. 导师可能追问的 6 个问题（标准答案）

| 导师问题 | 回答要点（30 秒内） |
|---|---|
| 1. 跟 Duolingo / 背单词 App 有什么不一样？ | **不是词汇量训练，是文化语用训练**。重点在"什么情况下怎么说才礼貌/合适"——这是跨文化对比的结果，Duolingo 不会告诉英语学生「我吃饱了，谢谢」不是饱是礼貌拒绝。 |
| 2. 数据从哪来？会不会凭空编？ | ① Supabase 文化知识表人工 seed（cultural_knowledge_points）；② Neo4j 391 节点人工迁移；③ LLM 生成后必须过 A5 三层质量门，confidence<0.6 的不入库。现场演示的 8 个案例我提前通过 CLI 预热，保证稳定。 |
| 3. 5 个智能体各自温度为什么都是 0？ | 论文对比实验的需要。消融实验设计要求贪心解码（temperature=0），让差异只来自架构本身，而不是采样随机性。实际教学可以调到 0.6–0.8 增加多样性，在 .env 用 LLM_A2_MODEL 等环境变量覆盖。 |
| 4. 如果 LLM 出了坏内容怎么防？ | 三层：① A3 偏见检测（关键词+句式）>0.2 标 FLAG；② A4 Solver 盲解对抗（盲猜答案和正确答案不一致 → REJECT）；③ HSK 超纲字硬规则（字表白名单过滤）。三层任一失败 → confidence < 0.6 → REJECTED，不进有效缓存池。 |
| 5. 缓存 key 为什么按 (kp, hsk, scene, culture) 四元组？ | 跨语言隔离——之前出过「日语请求命中英语阐释」的 bug，因为 target_culture 没纳入主键。修复后每种母语各占独立缓存行，避免互相污染。 |
| 6. 注册登录的 JWT 存在哪？安全吗？ | JWT 存 httpOnly SameSite=Strict Cookie（client 侧 JS 拿不到），bcryptjs 12 轮哈希密码，连续 6 次密码错误锁定 15 分钟，限流 6 次/分钟。`auth_schema.sql` 建 `auth_users` 表，和 `learners` 表互相 FK 绑定游客。 |
