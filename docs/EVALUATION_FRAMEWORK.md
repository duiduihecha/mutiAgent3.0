## 1. "好"的四个层次

```
层次1: 格式对不对     → JSON有效、答案可判       ← 
层次2: 内容准不准     → 文化事实不编造、词汇不超纲  ← 
层次3: 教学好不好     → 题有梯度、解释能让人懂     ←
层次4: 对不同文化公不公平 → 英语和阿拉伯语质量差多少  ← ★
```

## 2. 评估框架总览

不要列一堆平铺指标。按**三个维度**组织，每个子维度回答一个具体问题：

| 维度 | 要回答的问题 | 核心指标数 |
|------|------------|-----------|
| **维度一：生成质量** | 内容本身好不好看、准不准？ | 5个 |
| **维度二：文化公平性** ⭐ | LLM对不同文化公平吗？KG能改善吗？ | 3个 |
| **维度三：协同有效性** | 多Agent分工到底有没有用？每个Agent贡献多少？ | 3个(消融) |

## 3. 维度一：生成质量（Generation Quality）

> 内容本身好不好看、准不准

| 子维度 | 测什么 | 怎么测 | 谁测 |
|--------|--------|--------|------|
| **准确性** | 文化事实是否错误、中文例句是否通顺 | ①JSON格式正确率 ②HSK词表覆盖率 | 自动 |
| **适切性** | 内容难度是否符合目标HSK等级，母语解释是否针对该文化圈定制 | ①HSK词表覆盖率(词级别) ②AI裁判"个体适配性"评分 | 自动+AI裁判 |
| **丰富度** | 题型是否多样、解释是否深入 | ①题型种类 ②词汇多样性(TTR) | 自动 |

### 3.1 准确性

**JSON格式正确率**：

检查 `GeneratedContent` 结构完整性（`cultural_context.explanation`、`language_points`、`comparison`、`exercises` 必须存在且格式正确）。

**HSK词表覆盖率**：

从 exercises + language_points 中提取中文词语（2-3字滑动窗口），逐一查 Neo4j `HSKWord` 节点。如果在 HSK 词表中找到，且等级 ≤ 目标 HSK 等级 → 在纲。

```
覆盖率 = 在纲词数 / 总词数
```

### 3.2 适切性

**同上 HSK 词表覆盖率**的维度拆分：额外报告"超纲词率"（在词表但等级超了）和"不在词表率"（可能是 LLM 编造的中文词）。

**AI裁判"个体适配性"评分**：双 LLM（DeepSeek + Qwen）按 1-5 分评分，取平均。

### 3.3 丰富度

**题型种类**：统计 exercises 中 `type` 字段的不同值个数。

**词汇多样性（TTR）**：

```
TTR = 去重中文字符数 / 总中文字符数
```

## 4. 维度二：文化公平性（Cultural Fairness）⭐

> 这是你论文的核心贡献——别人没做过的。这三个子维度合在一起回答一个问题：
>
> **"LLM 给日语学习者写的'餐桌礼仪'课，跟给阿拉伯语学习者写的相比，是不是更好？差距有多大？KG 能缩小这个差距吗？"**

| 子维度 | 测什么 | 怎么测 | 谁测 |
|--------|--------|--------|------|
| **文化一致性** | 生成内容是否与KG中该KP的定义一致（不跑题） | KG事实一致性（新版的3项检查：domain/scene体现 + 关联概念命中 + 文化维度匹配） | 自动（需Neo4j） |
| **文化偏见度** | 对不同母语圈的内容是否存在系统性偏见差异 | 按文化圈分组的偏见度均值对比 + 方差分析（ANOVA） | 自动 |
| **文化适配度** | 对远近文化圈的适配质量是否有显著差异 | 文化距离(Hofstede欧氏距离) vs 各质量指标的 Spearman 相关性 | 自动+统计 |

### 4.1 文化一致性（KG事实一致性新版）

不从生成文本中提取关键词搜 KG（旧版问题：英文内容提不出中文关键词）。改为查该 KP 在 KG 中的 ground truth，再检查生成内容是否体现：

```
1. 从 Neo4j 查 ground truth:
   MATCH (d:Domain)-[:HAS_SCENE]->(s)-[:HAS_KNOWLEDGE_POINT]->(kp{id})
   MATCH (kp)-[:RELATES_TO]->(cc:CulturalConcept)
   MATCH (kp)-[:RELATES_TO]->(:CulturalConcept)-[:HAS_DIMENSION]->(cd)

2. 三项检查:
   ① Domain/Scene 名称是否在生成内容中体现?
   ② 关联文化概念有多少个被提及?
   ③ A3使用的文化维度框架是否与KG标注一致?

一致性 = 通过检查数 / 总检查数
```

### 4.2 文化偏见度（跨文化圈差异分析）

不是看单个样本的偏见度，而是看**不同文化圈的偏见度均值是否显著不同**：

```
按母语分组，计算每组的偏见度均值:

  日语(近):     偏见度平均 8%
  英语(中):     偏见度平均 12%
  阿拉伯语(远):  偏见度平均 28%

→ 单因素ANOVA: F(2, N) = ?, p < 0.01
→ 结论: 文化圈对偏见度有显著影响，远文化圈偏见系统性偏高

加入KG后:
  日语(近):     偏见度平均 7%
  英语(中):     偏见度平均 10%
  阿拉伯语(远):  偏见度平均 12%

→ ANOVA: F(2, N) = ?, p = 0.23 (不显著)
→ 结论: KG抹平了跨文化偏见差异
```

### 4.3 文化适配度（文化距离相关性）

**文化距离的计算**：

从 Neo4j SCORES 边读取每个 HomeCulture 在 6 个 Hofstede 维度上的分值，计算与中国文化圈(hc_zh)的欧氏距离：

```
CulturalDistance(hc_X) = sqrt(
  (score_zh.power_distance - score_X.power_distance)² +
  (score_zh.individualism   - score_X.individualism)²   +
  (score_zh.masculinity      - score_X.masculinity)²      +
  (score_zh.uncertainty      - score_X.uncertainty)²      +
  (score_zh.long_term        - score_X.long_term)²        +
  (score_zh.indulgence       - score_X.indulgence)²
)
```

然后用 Spearman 相关系数检验：

```
H₀: 文化距离与生成质量无显著相关
H₁: 文化距离与生成质量呈负相关（距离越远质量越差）

无KG时:
  r(文化距离, 偏见度)      = +0.72, p < 0.01  ← 显著正相关
  r(文化距离, KG一致性)    = -0.65, p < 0.01  ← 显著负相关
  r(文化距离, AI裁判总分)  = -0.58, p < 0.05  ← 显著负相关

有KG时:
  r(文化距离, 偏见度)      = +0.15, p = 0.42  ← 不再显著
  r(文化距离, KG一致性)    = -0.20, p = 0.31  ← 不再显著
  r(文化距离, AI裁判总分)  = -0.10, p = 0.55  ← 不再显著

→ 结论: 无KG时LLM对远文化圈有系统性质量下降；KG注入后这种不公平被消除
```

**这是这篇论文最具发表价值的发现。**

## 5. 维度三：协同有效性（Collaboration Effectiveness）

> 多Agent分工到底有没有用？每个Agent贡献多少？贡献模式是否因文化圈而异？

| 子维度 | 测什么 | 怎么测 | 谁测 |
|--------|--------|--------|------|
| **架构贡献度** | 每个Agent去掉后，质量下降多少 | C1-C5 消融对比（5条件 × N样本） | 自动 |
| **KG贡献度** | KG注入后，各维度提升多少 | Full+KG vs NoKG 对比 | 自动 |
| **文化距离交互** | Agent贡献是否因文化圈而异 | 文化距离 × Agent消融的交互效应（ANOVA交互项） | 统计 |

### 5.1 架构贡献度（消融实验）

5个条件，控制其他变量不变，只改变流水线结构：

| 条件 | 流水线 | 验证假设 |
|------|--------|---------|
| C1_Full | A1→A2+A3(并行)→A4→A5+KG | 基线 |
| C2_NoAgent_Monolith | 1个"全栈设计师"prompt直调LLM | 多Agent vs 单体 |
| C3_NoA3 | A1→A2→A4→A5+KG | A3文化对比的贡献 |
| C4_NoA5 | A1→A2+A3→A4+KG | A5质量管控的贡献 |
| C5_NoA2A3 | A1→A4→A5+KG | A2+A3阐释和对比的贡献 |

每个条件与其他条件成对比较，在所有指标上的差异。

### 5.2 KG贡献度

| 条件 | 描述 |
|------|------|
| Full+KG | A2/A3/A4 从 Neo4j 读取图谱数据注入 prompt |
| NoKG | A2/A3/A4 仅依赖 LLM 参数知识，不查询图谱 |
| RAG_only | 用向量检索替代图谱查询（对比结构化KG vs 非结构化RAG） |

### 5.3 文化距离交互效应

这是把维度二和维度三交叉分析——也是最具学术深度的分析：

```
9个文化圈 × 2个KP(近文化圈KP + 远文化圈KP) × 5个消融条件

双因素ANOVA:
  自变量1: 文化距离(近/中/远)
  自变量2: 消融条件(C1-C5)
  因变量: 偏见度、KG一致性、AI裁判总分

如果交互项显著:
  → A2母语阐释在"远文化圈"条件下去掉后，质量下降 > "近文化圈"
    (因为远文化圈学习者更需要母语打底)
  → A3文化对比在"近文化圈"条件下去掉后，质量下降 > "远文化圈"
    (因为近文化圈更需要精细对比来区分细微差异)

→ 结论: "不同文化场景需要不同的Agent策略"
```

## 7. AI 裁判评分维度

> 双 LLM（DeepSeek + Qwen）盲评，5 维度 × 1-5 分。裁判模型与生成模型（豆包）不同，避免自评偏差。

### 7.1 五个评分维度

| # | 维度 | 测什么 | 1分 | 3分 | 5分 |
|---|------|--------|-----|-----|-----|
| **1** | **准确性** | 文化描述对不对，中文例句语法通不通 | 严重错误，例句有明显语病 | 基本准确，有1处小错 | 全部准确，引用了恰当的文化背景 |
| **2** | **文化适切性** | 跨文化对比是否客观，有没有刻板印象 | 明显偏见或猎奇化表述 | 基本客观但不够深入 | 精细有分寸，避开所有刻板陷阱 |
| **3** | **教学有效性** | 练习题设计是否合理，能检测理解 | 题与目标无关或答案有误 | 基本可用但没层次 | 题目有梯度，选项有区分度 |
| **4** | **个体适配性** | 难度匹配HSK等级吗，母语适配做了吗 | 完全不对应等级和母语 | 大致匹配 | 精准匹配，学习者能直接关联自身经验 |
| **5** | **整体质量** | 这份内容能直接拿来教学吗 | 完全不可用 | 基本可用但需小改 | 可直接当教学模板 |

### 7.2 评分流程

```
同一个样本（盲评，不知道是哪个条件生成的）：
  → Judge 1 (DeepSeek) 打分 → {准确性:4, 文化适切性:3, 教学有效性:4, 个体适配性:4, 整体质量:4}
  → Judge 2 (Qwen)     打分 → {准确性:4, 文化适切性:4, 教学有效性:3, 个体适配性:4, 整体质量:3}
  → 取平均               → {准确性:4.0, 文化适切性:3.5, 教学有效性:3.5, 个体适配性:4.0, 整体质量:3.5}
  → 计算两裁判一致性     → Krippendorff's α = 0.82（高一致性，评分可信）
```

### 7.3 为什么用两个不同的 LLM

- DeepSeek（Judge 1）和 Qwen（Judge 2）都不是生成内容的模型（豆包/Doubao）
- 避免"自己评自己"的偏差——如果让豆包评自己生成的内容，天然会打高分
- 两个裁判独立评分后计算 Krippendorff's α，α ≥ 0.8 说明评分可信

### 7.4 抽样策略

分层抽样：按 condition × native_language × hsk_level 均匀抽取，每层取 2 条。约 40-60 个盲评样本。

### 7.5 代码位置

| 文件 | 作用 |
|------|------|
| `src/lib/ai-judge.ts` | AIJudge 类：构建含 Rubric 的 System Prompt，调用两个裁判评分 |
| `scripts/run-ai-judge.ts` | 运行脚本：读实验数据 → 分层抽样 → 双裁判评分 → 汇总输出 |

```bash
# 等实验跑完后执行
npx tsx scripts/run-ai-judge.ts --input experiment_results --sample-size 8
```

## 8. 各指标计算公式

### 7.1 自动指标（8个）

#### ① JSON格式正确率

```
检查 GeneratedContent 结构完整性:
  cultural_context.explanation     存在且为 string?  → 缺→不合格
  language_points                  非空数组?          → 空→不合格
  comparison                       对象存在?          → 缺→不合格
  exercises                        非空数组?          → 空→不合格
  exercise[i] 都有 type+question+correct_answer?     → 缺→不合格
  选择题 options 至少2个?                            → 不足→不合格

正确率 = 全部通过数 / 总样本数
```

#### ② HSK词表覆盖率（词级别，Neo4j验证）

```
1. 从 exercises + language_points 提取中文文本
2. 2-3字滑动窗口切分中文词语
3. 取前50个去重词，逐一查 Neo4j:
     MATCH (w:HSKWord {lemma: $word}) RETURN w.level
4. w.level ≤ targetHSK → "在纲", w.level > targetHSK → "超纲", 未命中 → "不在表"

覆盖率 = 在纲词数 / 总词数
```

#### ③ KG事实一致性（新版，与KP的Ground Truth比较）

```
1. 从 Neo4j 查 ground truth (domain/scene/pragmatic_intent/related_concepts/cultural_dimensions)
2. 三项检查:
   ① Domain/Scene 名称是否在生成内容中体现?
   ② 关联文化概念命中率
   ③ 文化维度框架是否与KG标注一致
3. 一致性 = 通过检查数 / 总检查数
```

#### ④ 偏见度

```
detectBias() 函数:
  关键词扫描: 17个偏见词（"所有/都/必须/从来/落后/保守/神秘的东方"...）
    命中1个 → score += 0.1
  句式扫描: 3个正则模式
    命中1个 → score += 0.2

bias_score > 0.2 → has_bias = true
```

#### ⑤ 题型种类

```
统计 exercises 中 type 字段的不同值个数
```

#### ⑥ 词汇多样性（TTR）

```
TTR = 去重中文字符数 / 总中文字符数
```

#### ⑦ 答案可判率

```
逐题检查:
  选择题: correct_answer 是选项字母 + 正确选项内容唯一
  判断题: correct_answer 是"对"或"错"
  填空题: correct_answer 非空

可判率 = 有效题数 / 总题数
```

#### ⑧ 平均耗时

```
记录每个Agent的start/end时间戳，相减得到耗时
并行Agent取最长（max(A2, A3)）
```

### 7.2 文化距离（Hofstede欧氏距离）

```
CulturalDistance(hc_X) = sqrt( Σ(score_zh[i] - score_X[i])² )

其中 i ∈ {power_distance, individualism, masculinity, uncertainty, long_term, indulgence}
score来源于 Neo4j SCORES 边（标注 confidence=High 的6个Hofstede维度）
```

### 7.3 统计检验

| 分析 | 方法 | 条件 |
|------|------|------|
| 两组均值比较 | 独立样本 t 检验 | 正态性 + 方差齐性 |
| 多组均值比较 | 单因素 ANOVA + Tukey HSD 事后检验 | 正态性 + 方差齐性 |
| 相关性 | Spearman 秩相关 | 非参数，不要求正态性 |
| 交互效应 | 双因素 ANOVA | 正态性 + 方差齐性 |
| 效应量 | Cohen's d (t检验) / η² (ANOVA) | 所有显著性检验报告效应量 |
