# COLING 2027 投稿计划方案
## 题目方向：基于多智能体 LLM 的母语感知跨文化中文学习系统 —— 架构、消融与质量网关

> 本文档为**投稿执行计划**，不含论文正文与代码实现。所有对系统的描述均锚定 `mutiAgent3.0` 真实代码（见 `src/lib/learning-graph.ts`、`multi-agent-system.ts`、`constants.ts` 等），并诚实标注「已实现 / 待完成」。
> 投稿通道：ACL Rolling Review (ARR) 2026 年 10 月周期，承诺至 COLING 2027（截止 2026-10-12 UTC-12，会议 2027-05-09~14，澳门）。

## 1. 选题与研究问题（符合 COLING 范围）

### 1.1 目标会议主题映射
COLING 2027 的相关主题中，本工作可同时命中 4 个：
- **NLP for Language Learning / Language Acquisition**（核心主题）
- **Cross-lingual and Multilingual NLP**（8 大母语文化圈）
- **Agent-based LLM Systems**（A1–A5 多智能体编排）
- **Ethics, Bias, Fairness, Alignment**（A3 偏见检测、文化适配）

### 1.2 论文定位（一句话）
一个**以知识图谱为锚、以贝叶斯知识追踪为调度、以质量网关为兜底**的母语感知跨文化中文学习多智能体系统，并用**系统化 agent 消融 + 离线 LLM 评判 + 真实用户反馈**验证每个组件对「内容相关性 / 文化适配 / 记忆保持 / 内容质量」的边际贡献。

### 1.3 研究问题（RQ）
| RQ | 问题 | 对应真实用户反馈 | 验证手段 |
|----|------|------------------|----------|
| **RQ1** | 多智能体分解（A1–A5）相比单体 LLM 是否在内容质量与文化适配上更优？ | 总体「体验差」 | C1 vs C2 消融 + CIEval |
| **RQ2** | 知识图谱锚定的场景路由相比模糊检索是否降低「答非所问」？ | P1 答非所问 | KG 路由修复前后对比（见 `getKnowledgePointByScene` 修改） |
| **RQ3** | BKT + 遗忘衰减的间隔复习调度是否提升跨文化知识点记忆保持率？ | P2 学了就忘 | 有/无 `next_review` 调度的前后测对比 |
| **RQ4** | A5 质量网关（硬门控）作为**成本/安全/尾例拦截**机制，能否在不拉低质量均分的前提下拦截低质尾例、并以缓存准入置信度节省成本？ | P4 偶发低质 | C4(NoA5) vs C1：低质触达率 + 缓存命中率 + 单位成本（**不主张质量均分提升**） |
| **RQ5** | 母语感知的情感/降难度干预是否提升学习者主观支持感？ | P3 干预不准 | 离线母语×焦虑档位话术评测 +（可选）用户研究 |

> 叙事主线：把上一阶段定位的 4 个真实系统缺陷（P1–P4）作为本论文的**动机与消融维度**，证明多智能体编排是修复正确性/一致性缺口的有效手段——比「又造一个教育 Agent 系统」更有说服力。

## 2. 系统架构与核心创新点（基于真实代码）

### 2.1 架构（活跃管线 = LangGraph 版 `learning-graph.ts`）
```
用户选 母语/HSK/场景
  → 场景映射 getKnowledgePointByScene()【SCENE_TO_KP_KEYWORDS + 打分排序】  ← P1 修复点
  → A1 学习者画像(纯数学: 文化焦虑度 + BKT)         [multi-agent-system.ts:LearnerProfilerAgent]
  → A2 母语阐释(LLM) // A3 跨文化对比(LLM + detectBias 偏见检测)  并行
  → A4 内容生成(LLM, 90s 超时, validateExercisesFormat 格式校验)
  → A5 质量网关(LLM 评分 + 二次审核)                [拟从 advisory 升级为 hard gate]
  → Neo4j 知识图谱(语义锚定 + 关系检索)
  → BKT 后验 + 遗忘衰减 → needsReview → (待接) next_review 调度   ← P2 修复点
  → 缓存(Supabase) / CIEval 评测
```

### 2.2 创新点（诚实分级）
| # | 创新点 | 状态 | 代码/资产锚点 |
|---|--------|------|----------------|
| **I1** | 五角色智能体编排（焦虑画像 / 母语阐释 / 跨文化对比+偏见检测 / 内容生成 / 质量网关） | ✅ 已实现 | `multi-agent-system.ts` A1–A5；`learning-graph.ts` |
| **I2** | 知识图谱（Neo4j）锚定的场景→知识点语义路由 | 🟡 部分（路由消歧已修，KG 复用待补） | `constants.ts:SCENE_TO_KP_KEYWORDS`；`getKnowledgePointByScene` 打分排序（已改） |
| **I3** | BKT + 遗忘衰减的掌握度追踪与复习调度 | 🟡 算法已实现，调度未闭环 | `bayesianKnowledgeTracing`；`learner-graph.ts` needsReview（缺 `next_review`） |

## 3. AI 协作工具分工（统一后端 = DeepSeek/MiniMax/GLM，零额外成本）

> **后端锁定（与开题一致）**：论文所研究的 mutiAgent3.0 系统，其 agent 后端**继续用开题的 DeepSeek / MiniMax / GLM**，不切 GPT、不补 GPT 对比基线——既与毕设口径一致，又零额外 API 成本。AI 辅助「写论文」的过程工具（见 §8 论文生产智能体架构）同样跑在这套零成本后端上；若偶发需要英文润色可用 ChatGPT，但**不作为系统 backbone、不作为对比基线**，且须在 AI 披露中说明。
>
> 原则：AI 工具辅助**研究过程**（设计、实现、分析、起草），但所有结论/数据须可复现、可审计；最终需按 ARR 政策披露 AI 使用情况。

### 3.1 ChatGPT（推理/写作型，o 系列或 GPT-5 级）用途
1. **文献调研与综述**：给定关键词（multi-agent education, LLM tutoring, cross-cultural NLP, knowledge tracing, quality gate），生成带真实出处的 related work 骨架，再人工核对 ACL Anthology / arXiv 原文（防编造）。
2. **假设与 RQ 打磨**：把 P1–P4 用户反馈转写为可检验 RQ，ChatGPT 提供对照 framing（如与 MALPP、deterministic-verification 工作对比）。
3. **方法章节起草**：将已实现组件写成可发表的 Method 描述（agent 职责、prompt 设计原则、BKT 公式），人工核对与代码一致。
4. **评估 rubric 设计**：设计 LLM-as-judge 的文化适配 / 主题相关 / 练习正确性维度与评分细则（用于 RQ2/RQ4）。
5. **Limitations & Ethics 起草**：强制章节，ChatGPT 列点（样本偏差、仅 8 母语、API 成本、文化内容偏见风险），人工定稿。
6. **语言润色**：把中文教育学概念准确译为学术英文。

### 3.2 Codex（编码型 agent）用途
1. **消融脚本整合**：把现有 C1–C5 条件统一封装为可复跑评测入口（参考已完成的 T45–T50 干净消融改造）。
2. **缺失模块实现**：① A5 hard gate（拦截/回退逻辑）；② BKT 的 `next_review` 字段与复习排序加权；③ KG 路由打分（已手写，Codex 补单测）。
3. **数据分析 pipeline**：用 pandas/scipy 计算 CIEval 各条件配对检验（Wilcoxon/配对 t）、低质率置信区间、记忆保持前后测效应量；自动出图（matplotlib/seaborn）。
4. **CI 校验**：提交前跑 `tsc --noEmit` + 已有 vitest，确保改动不破坏链路。
5. **复现包整理**：生成匿名化 README、环境依赖、prompt 清单（放附录）。

> **工作流**：Codex 在隔离沙箱生成并自测代码 → 人工 review diff（重点审「是否真改对」而非「看起来对」）→ 接入真实 Supabase/Neo4j 跑评测。绝不把 Codex 输出当最终结果，必须过人工审计与统计显著性检验。

## 5. 预期贡献与 Baseline 对比

### 5.1 预期贡献
1. 一个**知识图谱锚定 + 母语感知**的跨文化二语学习多智能体框架（I1/I2/I6）。
2. **系统化 agent 消融**证据：量化 A2/A3/A5 各自边际贡献（I5 + C1–C5）。
3. **BKT 间隔复习调度**对记忆保持的提升（I3）。
4. **质量网关升级为硬门控**作为成本/安全/尾例拦截的实证：低质触达率归零 + 缓存准入置信度节省推理成本，且**不牺牲质量均分**（I4，与开题 −0.15 不显著结论一致）。
5. 一份面向跨文化 L2 学习的**评估协议（CIEval 扩展）**：主题相关性 + 文化适配 + 练习正确性 + 偏见率。

### 5.2 Baseline 设置（全部复用现有 C1–C5 条件，零额外建模成本）
| 编号 | 配置 | 衡量什么 |

| **B3 NoA2A3** | C5：跳过母语阐释+跨文化对比 | 跨文化组件价值（RQ1/RQ3 文化侧） |
| **B4 NoSchedule** | 关闭 `next_review` 调度（现状） | 复习调度价值（RQ3） |
| **Ours (C1)** | 全链路 + 修复后 | 完整系统 |

## 8. 论文生产智能体协作架构（主 Agent + 子 Agent）

> 用「多智能体系统写关于多智能体系统的论文」的元层设计：把论文生产拆成 **1 个主 Agent（P0）+ 7 个子 Agent（S1–S7）**，按论文生命周期分工；其中 **S7-Gate 是元层质量门，刻意镜像 subject 系统 A5 的「网关拦截」哲学**——既是生产力工具，也是可写进论文的 self-demonstrating 卖点。全队运行在开题后端 DeepSeek/MiniMax/GLM（零额外成本）。

### 8.1 角色与分工
| Agent | 角色 | 论文阶段 | 镜像 subject | 核心职责 |
|-------|------|----------|--------------|----------|
| **P0 总控（论文 PI）** | 主 Agent | 全程 | — | 持有锁定口径（A5=成本/安全/尾例、后端=DeepSeek/MiniMax/GLM、CIEval 四维、6 组消融、8 页限、ARR 双盲）；排期（P1–P5）；派发任务；整合子 Agent 产出；阶段 go/no-go 与「毕设↔论文」一致性仲裁 |
| **S1-Lit** | 子·文献调研 | P1 | A2 阐释 | 调研 related work（多智能体教育消融 / MALPP / deterministic-verification / cross-lingual NLP），建文献库，定位 gap |
| **S2-Method** | 子·方法设计 | P2 | A4 生成 | 把 5-Agent + 4 层 KG(L1–L4) + BKT + A5 闸门写成可发表 Method；对齐开题 6 组消融（C1–C6） |
| **S3-Exp** | 子·实验执行 | P3 | A2/A4 代码 | 封装 `cieval_consistency.ts`，跑 C1–C6 于 DeepSeek/MiniMax/GLM，收原始结果 |
| **S4-Stat** | 子·数据分析 | P3 | A1 画像 | pandas/scipy：CIEval 聚合、Wilcoxon 配对检验、效应量、LaTeX 表与图 |
| **S5-Write** | 子·写作 | P4 | A4 生成 | 起草各章节、学术英文、强制 Limitations、控 8 页 |
| **S6-Ethics** | 子·伦理匿名 | P5 | A3 偏见检测 | ARR 双盲合规、脱敏、AI 披露、文化偏见声明、成本/碳披露 |
| **S7-Gate（元 A5）** | 子·质量门 | P5 | **A5 网关** | 投稿前终检：口径一致性（A5 价值/CIEval 维/消融组/后端不与毕设矛盾）、格式、匿名性；拦截缺陷后再投稿 |

### 8.2 协作流
`P0 派发 → S1(文献) → S2(方法) → S3(实验) ∥ S4(统计) → S5(写作) → S6(伦理) → S7(门禁) → 投稿`。P0 在每个阶段出口做一致性仲裁，**重点防「论文 vs 开题」口径打架**（CIEval 维度、消融组数、A5 价值表述、后端型号必须一致）。

### 8.3 为何是 8 个（1 主 + 7 子）
- **主 Agent 不可省**：跨阶段一致性（毕设↔论文）必须由单一中枢持有，否则各子 Agent 各写各的、出矛盾。
- **7 个子 Agent 对应 5 个生命周期阶段**：文献/方法/实验/统计/写作/伦理/门禁；其中实验(S3)与统计(S4)在 P3 **并行**以省时（7 周窗口紧）。
- **S7-Gate 单列**：把 subject 系统的 A5 哲学「复用」到论文生产本身——既提升效率，又成为论文叙事的活样例（self-demonstrating），与 §2.2 I4 形成呼应。
